# راهنمای نسخه جدید مدیریت فایل‌ها

این بسته روی همان ساختار Server Portal قبلی ساخته شده است. تغییرات مربوط به «مدیریت فایل‌ها» در پنجره مدیریت فاکتور است و **فایل‌های آپلودشده قدیمی یا پایگاه داده را حذف نمی‌کند**.

## چه چیزی تغییر کرده؟

- بازطراحی کامل پنجره مدیریت فایل با چیدمان هماهنگ با پنل فارسی، خلاصه تعداد/حجم، نمایش شبکه‌ای یا فهرستی، جست‌وجو و فیلتر نوع فایل و مرتب‌سازی.
- امکان انتخاب چند فایل، رهاکردن (Drag & Drop)، صف آپلود و نمایش درصد آپلود و لغو بارگذاری در حال انجام.
- نمایش بندانگشتی تصاویر و ویدیوها در صورت امکان؛ نمایش داخلی عکس، ویدیو و PDF؛ دانلود مستقیم فایل اصلی و دانلود گروهی ZIP.
- تفکیک مدارک «فاکتور» و «سرور»، همراه با حفظ ترتیب سریال‌ها و نام‌گذاری استاندارد فایل‌های دریافتی.
- **ویرایش نام نمایشی فایل** بدون تغییر محتوای آن، و **جایگزین‌کردن فایل اصلی** بدون تغییر شناسه یا گروه فایل؛ نام فایل دریافتی متناسب با پسوند جدید بازسازی می‌شود.
- حفظ کیفیت و بایت‌های فایل اصلی و ساخت thumbnail جداگانه؛ آپلودها و جایگزینی فایل به‌صورت stream در سرور دریافت می‌شوند و فایل ۵۰۰ مگابایتی در حافظه Node به‌طور کامل ذخیره نمی‌شود.
- کنترل آپلود، ویرایش و حذف به‌صورت مستقل، در API و رابط کاربری.

## دسترسی کاربران

مشاهده، پیش‌نمایش و دریافت فایل‌های فاکتور برای **تمام کاربران واردشده** (ادمین، تکنسین فنی و کارشناس فروش) مجاز است و مستقل از مجوزهای تغییر فایل عمل می‌کند.

در «مدیریت کاربران» ← «ساخت/ویرایش کاربر» ← «دسترسی‌ها» یک گروه «مدیریت فایل‌ها» با سه مجوز ایجاد شده است:

| کد دسترسی | عملکرد |
|---|---|
| `media.upload` | بارگذاری فایل جدید فاکتور یا سرور |
| `media.edit` | تغییر نام نمایشی یا جایگزینی محتوای فایل |
| `media.delete` | حذف فایل ثبت‌شده |

مجوزهای سه‌گانه برای **همه کاربران دارای نقش تکنسین فنی** به‌صورت پیش‌فرض فعال هستند (نه فقط چند حساب کاربری ثابت). برای ادمین نیز فعال و برای کارشناس فروش به‌صورت پیش‌فرض غیرفعال هستند؛ می‌توان آنها را برای هر کاربر تغییر داد. از قبل غیرفعال‌کردن صریح یک مجوز جدید، اولویت دارد.

این مجوزها در زمان راه‌اندازی به‌صورت خودکار با داده‌های قبلی کاربرها یکپارچه می‌شوند؛ نیازی به اجرای دستی اسکریپت SQL نیست. حذف مجوز از UI به‌تنهایی نیست و در سمت سرور هم با پاسخ `403` کنترل می‌شود.

## روش نصب نسخه ZIP روی سرور

1. **قبل از جایگزینی، از پروژه، پایگاه داده و مخصوصاً مسیر `/root/portal-media` نسخه پشتیبان بگیرید.** کپی پوشه فعلی را نگه دارید.
2. فایل ZIP را باز و **محتوای پوشه آن** را در مسیر پروژه جاری خود جایگزین کنید؛ فایل `.env` فعال خود را مطابق تنظیمات سرور نگه دارید. ساختار پوشه‌ها تغییری نکرده است.
3. در پوشه پروژه اجرا کنید:

```bash
docker compose up -d --build app
docker compose restart web
docker compose ps
docker logs --tail 80 node_app
```

4. مرورگر را با `Ctrl + F5` تازه‌سازی کنید. کتابخانه فایل را برای یک فاکتور دارای سریال و مدارک قبلی باز کنید.

**توجه:** پوشه مدیا روی دیسک میزبان است و جزو فایل ZIP برنامه نیست. مسیر فایل‌های آپلودی موجود نباید پاک شود. `.env` و حجم ذخیره‌سازی قبلی پروژه باید در سرور واقعی بررسی و حفظ شوند.

## چک‌لیست تست پس از نصب

- با یک **کارشناس فروش عادی** وارد شوید. مشاهده، جست‌وجو، پیش‌نمایش و دانلود باید کار کنند؛ دکمه‌های آپلود/ویرایش/حذف نباید دیده شوند.
- با یک **تکنسین فنی جدید** وارد شوید. هر سه مجوز باید به‌طور پیش‌فرض فعال باشند؛ با برداشتن هر تیک باید فقط همان عمل از کار بیفتد.
- به یک **کارشناس فروش** فقط مجوز `media.edit` بدهید. نام فایل را تغییر دهد و سپس یک فایل دیگر جایگزین کند؛ بدون دسترسی آپلود/حذف.
- آپلود چند فایل PDF، عکس و ویدیو، همچنین فایل بزرگ‌تر از حد مجاز، فرمت غیرمجاز، دوباره‌بارگذاری فایل تکراری و لغو وسط آپلود را بررسی کنید.
- فایل‌های قدیمی، تصاویر پیش‌نمایش، دانلود ZIP هر سریال، و نام استاندارد دریافت فایل‌ها را بررسی کنید.
- جایگزینی فایل باید همان شناسه و گروه (فاکتور/سریال) را حفظ کند، و فایل اصلی قدیمی تنها پس از ذخیره موفق نسخه جدید حذف شود.
- پنجره را در موبایل و دسکتاپ و بخش دسترسی کاربران را تست کنید.

## تست خودکار همراه پروژه

```bash
docker exec node_app node --test test/invoice-media.test.js
```

آزمون‌ها شامل اعتبارسنجی فایل و سریال، پیش‌فرض مجوزها و قابلیت لغوشان، بررسی مسیرهای API بدون مجوز، تغییر نام با مجوز کارشناس فروش، و جایگزینی واقعی یک فایل در پوشه موقت هستند.

## محدودیت‌ها و نکات عملیاتی

- اندازه هر فایل حداکثر **۵۰۰ MiB**، مجموع فضای پرونده‌ها **۱۰۰ GiB** و رزرو فضای آزاد دیسک **۲ GiB** طبق نسخه اولیه حفظ شده‌اند.
- فقط فرمت‌های تعریف‌شده در سیستم (تصویر، ویدیو، PDF، Office و متن) مجاز هستند. فایل‌های HEIC/TIFF ممکن است بسته به مرورگر فقط thumbnail داشته باشند؛ دریافت اصل فایل همچنان ممکن است.
- فایل‌های ثبت‌شده در PostgreSQL صرفاً شامل فراداده هستند؛ **پشتیبان‌گیری از `/root/portal-media` الزامی است**.
- تست‌های همراه بسته و نمایش نمونه در مرورگر انجام شده‌اند؛ قبل از استفاده عملیاتی، تست نصب و آپلود/دانلود روی سرور دارای PostgreSQL واقعی نیز لازم است.
